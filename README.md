# 核雕3D图生成与雕刻机数据生成系统 MVP

这是基于《核雕3D图生成与雕刻机数据生成系统-落地方案V2.md》实现的第一版可运行 MVP。

## 当前已实现

1. 上传一张或多张核雕参考图片。
2. 可点击“载入示例图案”快速演示多图流程。
3. 可点击“载入素材01”使用 `public/test-assets/01/` 中的 6 张真实素材进行测试；V3 默认佛头回归样件记录在 `public/v3-fixtures/buddha-baseline.json`，可用 `npm run test:v3:buddha-fixture` 校验。
4. 点击“3D生成”，可按当前图片、多图平均融合或本地360°环绕浮雕（非AI Mesh）模式生成深度场。
5. 根据核长、直径、浮雕深度、包覆角度生成完整 360 度核胚 3D 浮雕预览。
6. 支持浏览器内旋转、缩放、平移查看 3D 模型。
7. 支持基础微调：核长、直径、深度、包覆角度、图像对比、平滑、深浅反转、网格显示。
8. 支持局部修模：在深度图上用笔刷加深、减浅、平滑局部区域，3D 模型实时更新。
9. 支持下载当前 3D 模型 `.stl` 文件，便于第三方软件复核。
10. 支持刀路参数：刀具直径、X 步距、旋转步距、进给、主轴转速。
11. 旧 MVP 可生成基础四轴扫描刀路；V3 主线已收敛到“三轴控制器 + Y 轴旋转夹具”的安全试雕流程。
12. 旧 MVP 支持通用四轴、维宏风格、新代风格后处理；V3 主线优先验证 `desktop-3axis-rotary-y` / `wrapY` 后处理。
13. 支持下载 `.nc`、`.tap`、`.txt` G-code 文件和 `.csv` 刀路点文件。
14. 生成刀路后在 3D 视图中叠加刀路轨迹，并显示 X/A 范围和基础安全提示。
15. 支持通过本地后端代理调用 Meshy Multi-Image to 3D，生成真实 GLB/STL AI 网格。

详细验收步骤见 [验收清单.md](./验收清单.md)。

## 本地运行

```bash
npm install
npm run dev
```

打开终端显示的本地地址，例如：

```text
http://127.0.0.1:5174/
```

```bash

```

构建产物会生成到 `dist/`。

## 当前刀路坐标约定

V3 目标设备按用户实际机型收敛为：

```text
X: 核雕长度方向
Y: 旋转夹具等效展开行程/角度步进
Z: 刀深 / 安全高度
刀具: 4mm 25 度平底尖刀
后处理: wrapY，仅输出 X/Y/Z，不输出 A 轴
```

旧 MVP 四轴预览仍保留工程入口，其坐标约定为：

```text
X: 核胚长度方向
A: 绕 X 轴旋转角度，单位 degree
Z: 径向刀具中心高度，单位 mm
```

输出 G-code 包含：

1. `G21` 毫米单位。
2. `G90` 绝对坐标。
3. `G94` 每分钟进给。
4. `S... M3` 主轴启动。
5. 旧 MVP 为 `G1 X... A... Z...` 四轴扫描刀路；V3 `wrapY` 输出为 `G1 X... Y... Z...`，并在头部声明 `ROTARY_WRAP_AXIS=Y`。

## 重要说明

当前版本已经包含早期前端 MVP 和 V3 Orchestrator 主线。早期 MVP 用于验证“图片到 3D 预览再到基础刀路”的核心流程；V3 用于验证“真实 3D 模型 -> 安全试雕包 -> CAM/仿真/机床证据回填”的工程闭环。它仍不是最终可直接量产的 CAM 内核。

下一阶段建议重点补齐：

1. 后端 Python/C++ 几何与 CAM 服务。
2. 真实核胚标定和夹具参数。
3. 目标雕刻机后处理器配置。
4. 过切、欠切、限位、夹具碰撞检查。
5. 实物试切后的误差补偿。
6. 更细的局部画笔修模和多图融合。

## Linux 服务器部署建议

如果需要部署到 Linux 服务器测试，可先采用静态站点方式：

```bash
npm install
npm run build
npx serve dist -l 8080
```

生产环境建议用 Nginx 托管 `dist/`，并把 `/api/*` 反向代理到 Node Orchestrator。V3 后端已经承担 Meshy 代理、任务队列、文件缓存、模型体检、外部 CAM 交接和安全门禁。

V3 Orchestrator 分支的部署请参考：

- `V3架构与小闭环验证.md`

### V3 本地启动

推荐使用一个命令同时启动 Orchestrator API 和前端：

```bash
npm run dev:v3
```

该命令会先检查端口占用：默认使用 API `8787`、前端 `5173`，如果端口已经被旧服务占用，会自动顺延到下一个可用端口，并把 Vite `/api` 代理指向同一个 API 端口。终端会打印本次可访问的 UI 地址，避免浏览器连到旧项目或旧 API。

## 本地360°环绕浮雕（非AI Mesh）说明

“本地360°环绕浮雕（非AI Mesh）”会把多张图片按顺序映射到核胚周向不同角度，生成一张环绕深度场，再形成完整 360° 包覆网格，并可继续生成四轴刀路。

当前实现属于可运行的前端雏形，不等同于工业摄影测量或神经重建。若要得到真正自由形态的完整 3D mesh，后续应接入后端多视角重建/AI 3D 生成服务，再进入 CAM。

## Meshy AI 3D Mesh

Meshy API Key 放在本地 `.env` 文件中，前端不会直接读取密钥。

启动本地 Meshy 代理：

```bash
npm run api
```

另开终端启动前端：

```bash
npm run dev
```

页面中点击“Meshy生成3D Mesh”会取当前素材列表前 1-4 张图片调用 Meshy Multi-Image to 3D。生成完成后可预览 GLB，并下载 GLB/STL。V3 后端 CAM 导入当前支持 `.stl/.obj/.glb/.gltf`，其中 OBJ 已纳入 `npm run test:v3:small-loop-acceptance` 小闭环验收。
